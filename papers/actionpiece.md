# ActionPiece：上下文动作序列分词

> ActionPiece 根据同一动作内及相邻动作间的特征共现关系压缩行为序列，减少生成式推荐中的序列长度。

## 研究动机与问题定义

将每个动作展开为多个特征 token 会造成序列过长，并损失动作上下文。ActionPiece 关注的是行为序列的上下文分词效率，而不是为每个物品学习并直接生成完整 SID。

## TL;DR（核心摘要）

`动作序列 → 共现统计 → ActionPiece 词表 → 序列压缩 → 生成式推荐输入`

方法按加权共现关系迭代合并 token，并用集合排列正则减轻特征顺序影响。生成模型接收压缩后的动作序列；该过程不构成直接由完整 SID 确定推荐物品的在线链路。

## 方法设计

### 3.1 问题定义（Problem Formulation）
ActionPiece 将一次用户动作表示为无序物品特征集合，把一段行为历史表示为特征集合序列。目标不是学习物品 SID，而是为动作序列学习更短且包含上下文的 token 序列。

### 3.2 上下文动作序列分词器
词表从每个特征 token 初始化，通过统计同一集合内部和相邻集合之间的共现关系，反复合并高权重 token 对。由于集合内部无序，论文引入集合排列分段策略，为同一动作产生多个等价分词结果。

### 3.3 生成式推荐模型
压缩后的 ActionPiece 序列被送入生成式推荐模型训练。推理时模型生成动作 token，再解析回推荐动作/物品。论文还使用多种分段结果进行推理时集成，以降低某一种分段方式的偶然影响。

### 3.4 讨论与实验
实验分别考察序列长度、词表规模、token 利用率、分段策略和案例。该方法的核心对象是动作 token，不属于本项目定义的完整物品 SID 直接生成。

## 实验结论

- ActionPiece 能缩短动作序列，并改善 token 利用率。
- 上下文加权和集合排列正则对分词质量有贡献。

## 局限性与研究定位


### 局限性
- 其输出不是完整物品语义标识，不能按本项目标准归入核心方法。
- 对最终推荐物品的直接可解释映射不是论文重点。


### 研究定位
ActionPiece 更适合放在“生成式推荐的行为序列建模与分词”章节，而非 Semantic ID 直接生成章节。
